Plyrune CLI · v0.0.1-preview.2

Find the text. Review the change. Choose where it lands.

Tell Plyrune which folder to search and which text to replace. It shows every match and the files with none. Only a separate apply command writes files.

Use it when an agent or script needs to change every old_host under config/, not just the first one it found. Edit the originals or write a copy to another directory. No Git repository, commit or checkout required.

Linux x86-64 · including WSL2

Install the CLI

curl -fsSL https://plyrune-dev.github.io/install.sh | sh
"$HOME/.local/bin/plyrune" demo

demo is read-only: it shows an exact text lookup, then a stale lookup being refused. Try a real edit below.

The installer verifies the SHA-256 of the pinned binary. No sudo, Rust or Docker. Remove ~/.local/bin/plyrune to uninstall.

Shell / CI

Change a setting without touching the original

Try this on a local Linux filesystem. The example makes one input file, then writes the reviewed result to a separate empty directory. jq just reads the review ID from JSON; Plyrune itself does not need it.

1. Find and preview

p="$HOME/.local/bin/plyrune"
src=$(mktemp -d)
mkdir "$src/config"
printf 'host=old_host\n' > "$src/config/app.env"
"$p" refs --root "$src" config/ old_host
"$p" preview --root "$src" config/ old_host new_host \
  > "$src/review.json"
cat "$src/review.json"

One match in config/app.env: bytes 5–13 (end excluded). The preview names the original text, replacement, file hashes and review ID. The file still says host=old_host.

2. Choose the output directory

out=$(mktemp -d)
id=$(jq -er .review "$src/review.json")
"$p" apply --root "$src" config/ old_host new_host \
  --review "$id" --into "$out"
cat "$out/config/app.env"

The output reads host=new_host. For an intentional edit of the originals, use --in-place instead of --into "$out". If the reviewed source changed, stop and preview again; don’t silently use a new ID.

Evidence / scope

What Plyrune checks, and what it doesn't

Exact text, not symbols

refs finds literal UTF-8 byte sequences, including in comments or strings. It does not know whether two names refer to the same function. File scopes are explicit; a narrow scope cannot establish what you meant to change.

Review tied to the input

The review binds the source, task and candidate. The proof record covers named Rust kernel decisions. The installed CLI checks exercise actual files. Filesystem operations are tested, not proved.

One writer, one file at a time

Use a local tree you control; do not run another editor against it during apply. Each renamed file is visible separately. A crash can leave a mixed tree. Save the preview, compare before retrying, or prefer a separate output directory. Supported filesystem profile and recovery.
