Plyrune CLI · v0.0.1-preview.1

Read from the snapshot your agent saw.

For coding-agent and CI authors: a path and two offsets tell the next step where to read, but not which input you reviewed. Plyrune’s CLI checks the saved fixture digest before returning the text.

The demo reads legacy_endpoint from bytes 8–23 (end excluded) of config/server/api.env. Then it changes only docs/notes.txt in memory. Same path, same bytes, same request; this time the result is WrongSnapshot.

Linux x86-64 · including WSL2

Try the demo

curl -fsSL https://plyrune-dev.github.io/install.sh | sh
"$HOME/.local/bin/plyrune" demo

Both outcomes print as JSON. The demo exits successfully after showing the refusal.

The installer script checks the SHA-256 of the pinned preview binary and installs it in ~/.local/bin by default. No sudo, Rust or Docker needed. Remove the binary to uninstall.

Shell / CI

Pass the digest between steps

Use snapshot when your harness accepts the fixture, then pass that saved digest to inspect. Both read the fixture manifest on stdin, not the working tree. Try this in an empty directory with jq installed.

1. Inspect the original fixture

p="$HOME/.local/bin/plyrune"
"$p" example > fixture.json
key=$("$p" snapshot < fixture.json | jq -er .sha256)
view() {
  "$p" inspect "$key" config/server/api.env 8 23
}
view < fixture.json

Exit 0. The JSON field text contains legacy_endpoint. Offsets count UTF-8 bytes from zero; the end is exclusive.

2. Repeat after a different file changes

jq '(.resources[] |
  select(.path == "docs/notes.txt") |
  .text) += "!"' fixture.json | view

Exit 2. inspect writes WrongSnapshot to stderr and no view to stdout. Don’t treat that as empty text or silently substitute a new digest: decide whether to restart the step on the changed input.

Evidence / scope

What the refusal tells you

Proved for the release

The preview’s Lean proof record covers the translated Rust guard: different snapshot keys are refused; equal keys use the byte-range and UTF-8 checks. Ignoring either half of the key broke that theorem.

Tested, not proved

Digest encoding, path lookup and CLI behavior are tested separately. The installed-binary checks cover stale requests, invalid ranges and the display limit. A digest identifies input; it does not grant permission to read it.

Outside the preview

No workspace search, editing or migration check. There are no measured agent-task outcomes for speed, cost or success.

Source development · 25 November 2026

Keep the file identity, not just the text

Two config files can both say legacy_endpoint. The Rust library lets a harness keep a capture from one file and refuses to resolve it against the other. It binds the store, snapshot, resource and byte range. This is available from source, not in the installed CLI.

The next question is about coverage: did a migration replace every required occurrence under config/, or only the ones the agent inspected? That needs a complete inventory, including files with no matches. Neither the release nor a single capture answers it.
