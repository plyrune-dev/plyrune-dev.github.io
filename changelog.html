Changelog

What changed, how we checked it, and where you can try it.

26 November 2026 · v0.0.1-preview.2

Find references, preview replacements, then write real files

refs lists exact text occurrences. preview shows the replacement, byte ranges and per-file hashes without writing. apply requires the saved review ID and either --in-place or --into DIR. Git is not required; a separate destination can be new or already empty.

Try the two-step example. This is literal text replacement on a controlled local Linux filesystem, not a symbol rename or a multi-file transaction. The packaged consumer record and kernel proof record cover different parts of that workflow.

25 November 2026 · Rust library · source only

Same text, different file: refuse the capture

Open a path in an immutable fixture, retain a byte range, and resolve it later. A capture from one file cannot stand in for a capture from another, even when both contain identical text. A different store lifetime or snapshot also refuses. See the kernel proof and library controls.

The CLI preview is unchanged. The site now shows its actual shell workflow, and remembers your light or dark preference on this page as well as the homepage.

25 November 2026 · Proofs milestone

One-resource literal matching, checked separately from the preview

The source experiment proved that its Rust scan returns the first or all left-to-right, non-overlapping byte matches. Starting the scan one byte late broke the theorem. This is not a search command or proof of coverage across files.

The fixture contract now distinguishes the reusable task from who admitted it on a particular snapshot. The installable preview is unchanged: it inspects a byte range and refuses stale input.

24 November 2026 · v0.0.1-preview.1

Install Plyrune and try a stale snapshot

Install the Linux x86-64 CLI and run plyrune demo. It reads legacy_endpoint from a precise byte range, changes a different file in memory, and shows why the old inspection now refuses.

The sixth Lean claim covers snapshot-key equality and exact range refusal. Installed-binary controls cover path lookup, UTF-8, the display cap and the CLI. This preview does not edit files or certify a migration.

24 November 2026 · Development checkpoint

A reproducible reference for the first migration

Kernel proof: a range presented from a different owner or store incarnation is refused before its offsets are considered. For the same store, the exact text-range decision is preserved. The Lean gate record at this checkpoint covers five kernel claims, including this one. It does not establish full capture identity or migration coverage.

Now open source: build Plyrune from its MIT-licensed source. An optional Writfold gate checks fixture identity using the same command as standalone CI. This checks a snapshot, not the correctness of an edit.

The six native fixture tasks now record their actual outputs and the identities of their inputs. The build compares each rerun with the saved trace. One case shows why scope matters: replacing both matches under config/server/ still misses four required replacements elsewhere. These are correctness checks, not performance measurements.

Live on Pages: the assurance record separates the current developer build from planned operations. The measurement record has no benchmark trials yet.

23 November 2026 · Private source checkpoint

The first command identifies an immutable fixture

plyrune snapshot reads a fixture on stdin. It admits regular UTF-8 resources, preserves line endings, and returns a resource count and content digest. The installed command matched the independent digest for the five-resource example.

Assurance: the Docker gate checked four Lean claims over the translated Rust kernel: store equality, byte-range bounds, UTF-8 boundary detection and text-range admission. Six intentional source changes broke their expected theorems.

Editing: an isolated Splicery probe produced the expected candidate for all five resources. That is not yet an editing command or a proof of migration coverage.
